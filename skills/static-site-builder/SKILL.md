# Skill: Static Site Builder

## Назначение

Собирать быстрые адаптивные сайты для бизнеса из проверенных компонентов на HTML, CSS и vanilla JavaScript. Этот навык отвечает за реализацию, а не за выдумывание бизнес-фактов или самостоятельное исследование рынка.

## Входные данные

Обязательные:
- утверждённый бриф;
- sitemap и список страниц;
- утверждённый контент для каждой страницы;
- дизайн-система или согласованный визуальный референс;
- список языков и регионов;
- целевые действия (звонок, WhatsApp, форма, запись и т. п.).

Если критически важные данные отсутствуют, перечислить пробелы и запросить уточнение до реализации соответствующих частей.

## Технологические ограничения

1. Использовать HTML5, CSS и vanilla JavaScript.
2. Не подключать CMS, WordPress, React, Vue и другие фреймворки без отдельного обоснования и согласования.
3. Не добавлять библиотеку, если задачу можно решить коротким нативным кодом без ухудшения поддержки.
4. Предпочитать локальные файлы шрифтов и скриптов, когда лицензия и размер это позволяют.
5. Не помещать секреты, API-ключи и приватные токены в браузерный код.
6. Все внешние зависимости документировать в README с причиной использования.

## Порядок работы

1. Проверить входные документы и существующую структуру папки.
2. Создать семантическую структуру страниц.
3. Реализовать общие элементы: header, navigation, footer, CTA и повторяющиеся секции.
4. Создать CSS-токены: цвета, типографика, отступы, ширины контейнера, радиусы и тени.
5. Сделать mobile-first адаптивную вёрстку.
6. Реализовать интерактивность на vanilla JavaScript с доступным управлением клавиатурой.
7. Подключить формы только после определения реального endpoint или сервиса приёма заявок. Если endpoint отсутствует, явно пометить форму как демонстрационную и не имитировать успешную отправку.
8. Реализовать локализованные версии. Для RTL использовать dir и logical CSS properties.
9. Добавить метаданные и связи между языковыми версиями по утверждённому SEO-плану.
10. Запустить доступные проверки, исправить найденные ошибки и описать ограничения.

## Правила качества

- Один H1 на страницу, логичная иерархия заголовков.
- Контраст текста и фона, видимый focus, labels для полей форм.
- Alt-тексты для содержательных изображений; декоративные изображения не должны создавать шум для скринридера.
- Не использовать текст в изображениях как замену HTML-контенту.
- Не вставлять фиктивные отзывы, рейтинги, сертификаты или гарантии.
- Не добавлять тяжёлые анимации и autoplay-видео без причины.
- Проверять RTL не только на уровне текста, но и для навигации, карточек, иконок, форм и мобильного меню.

## Выходные артефакты

- работающие файлы сайта;
- README с локальным запуском и публикацией;
- список внешних зависимостей;
- отчёт о проверках;
- список незаполненных данных и ограничений.

## Критерии приёмки

Навык завершает работу только когда все страницы существуют, внутренние ссылки корректны, адаптивность и направление письма проверены, CTA ведут в ожидаемые места, а все ограничения и непроверенные интеграции явно указаны.
